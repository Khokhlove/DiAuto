# DiAvto

Веб-сервис для поиска автомобилей с пробегом на китайской площадке **che168.com** (二手车之家 / Autohome).

Пользователь выбирает марку, модель, годы, бюджет и пробег. Сервис запрашивает выдачу che168, находит **3 самых дешёвых и 3 самых дорогих** автомобиля, сохраняет детали и фотографии и показывает карточки с ценой в юанях и ориентиром в рублях по курсу ЦБ РФ.

Из карточки автомобиля можно сформировать **персональную карточку для клиента**: публичную страницу с фотографиями, характеристиками, страной нахождения и итоговой стоимостью под ключ. Доставка до Владивостока, доставка из Владивостока в город клиента, осмотр и растаможка автомобиля настраиваются в тарифах.

## Что уже готово

- Blazor Web App на **.NET 10** (Interactive Server).
- **EF Core 10 + SQLite**, миграции и сидер.
- ASP.NET Core Identity, вход в админку, роли `Admin` / `Manager`.
- Инструмент поиска (доступен после входа):
  - компактная страница поиска без публичного лендинга;
  - переключатель источников: che168.com и вторая вкладка-заготовка под будущий сайт;
  - подбор 3 + 3;
  - карточки с фото, характеристиками, ценой CNY/RUB и ссылкой на оригинал;
  - точные фильтры цены в юанях или рублях (пересчёт по курсу ЦБ) и пробега в километрах;
  - поиск по бюджету «под ключ»: из рублёвой суммы сначала вычитаются доставка, осмотр и растаможка, а остаток пересчитывается в юани;
  - плашка с расшифровкой бюджета: сколько уходит на каждую услугу и сколько остаётся на автомобиль;
  - детальная страница со всеми фотографиями и лайтбоксом;
  - курс CNY/RUB на странице поиска и в результатах;
  - последние запросы для быстрого перехода.
- Админка:
  - дашборд;
  - источники и проверка API;
  - каталог брендов/моделей с синхронизацией из che168;
  - история поисковых запросов;
  - автомобили и обновление деталей из источника;
  - курс валют и наценка;
  - интеграция che168 (параметры только для чтения);
  - пользователи, роли и права на отдельные разделы админки;
  - журнал действий;
  - тарифы доставки до Владивостока, доставки из Владивостока, осмотра и растаможки автомобиля;
  - карточки клиента со ссылкой на публичную страницу и возможностью отключить её.
- Публичная карточка клиента (`/card/{id}`) без входа:
  - фотографии и характеристики автомобиля;
  - страна нахождения и город покупки;
  - итоговая стоимость «под ключ» без внутренних расчётов и цен по отдельности;
  - комментарий менеджера и контакты;
  - дата формирования и зафиксированный курс расчёта;
  - печать/сохранение в PDF средствами браузера.
- Фоновое обновление курса ЦБ РФ.
- Интеграция с che168 через мобильный JSON API с подписью запросов, без браузерной автоматизации.
- Unit-тесты для подписи che168, курса и поисковых преобразований.

## Быстрый старт

Требуется **.NET 10 SDK**.

```powershell
cd E:\ChinaCars
dotnet restore
dotnet run --project src\DiAvto.Web\DiAvto.Web.csproj --launch-profile http
```

Приложение: [http://localhost:5204](http://localhost:5204)

При первом запуске EF Core применит миграции, создаст `Data/diavto.db`, роли, администратора, источник che168, вторую вкладку-заготовку и настройки. В фоне прогреется каталог брендов (≈639 брендов при первом запуске).

Страница поиска и карточки доступны только после входа: это внутренний инструмент, а не публичный сайт.

### Вход в админку

- URL: [http://localhost:5204/Account/Login](http://localhost:5204/Account/Login)
- Логин: `admin`
- Электронная почта: `admin@diavto.local`
- Пароль: `admin`

**Смените пароль после первого входа**: в админке нажмите «Пароль» в верхней панели или откройте `/Account/Manage/ChangePassword`. Логин/пароль задаются в `appsettings.json` → `Seed`. Для production используйте user-secrets или переменные окружения и обязательно отключите дефолтный пароль.

> Для внутреннего контура пароль упрощён до `admin`, а требования к сложности ослаблены в `Program.cs`. Перед production смените пароль и верните строгие правила.
```powershell
dotnet user-secrets --project src\DiAvto.Web\DiAvto.Web.csproj set "Seed:AdminPassword" "StrongPassword#2026"
```

## Карточки клиента

Карточка клиента — отдельная публичная страница, которую можно отправить человеку ссылкой. Вход на неё не требуется, остальные разделы сайта по-прежнему закрыты авторизацией.

1. **Админка → Тарифы** — заполните стоимость:
   - доставки из региона покупки до Владивостока;
   - доставки из Владивостока до города клиента (Владивосток, Хабаровск, Москва и другие города можно добавлять);
   - осмотра автомобиля в регионе покупки;
   - растаможки автомобиля.
2. **Админка → Автомобили → нужная машина → «Карточка клиента»**.
3. Выберите город клиента, тариф осмотра и растаможки. Система подставит тарифы доставки до Владивостока и растаможки по городу автомобиля, если они есть, иначе — тарифы по умолчанию.
4. Проверьте расчёт (он виден только сотруднику), укажите имя клиента и комментарий. Нажмите «Сформировать карточку».
5. Скопируйте ссылку и отправьте клиенту. Клиент увидит только итоговую стоимость под ключ, дату формирования и курс расчёта — без цен автомобиля, доставки, осмотра и растаможки по отдельности. Ссылка на оригинальное объявление на публичной карточке не выводится, остаётся текстовая подпись источника.

Суммы фиксируются в карточке в момент создания. Если позже изменить тарифы, уже отправленные клиентам предложения не изменятся. Ссылку можно отключить в **Админка → Карточки клиента**. Карточки, созданные до появления растаможки, сохраняют старую стоимость и не показывают её в составе предложения — чтобы включить растаможку, сформируйте карточку заново.

Публичный адрес сайта для ссылок (`http://...`) и контакты менеджера задаются там же, в разделе **Карточки клиента**. Если адрес не указан, используется адрес, по которому открыта админка.

## Как работает поиск

0. Сотрудник открывает страницу поиска, выбирает вкладку источника (сейчас che168, вторая вкладка — заготовка) и вводит параметры.
1. Пользователь выбирает марку и, при желании, модель.
2. Сервис синхронизирует список моделей выбранного бренда (кешируется в БД).
3. Если цена задана в рублях, сумма считается бюджетом «под ключ»: из неё вычитаются выбранные тарифы доставки до Владивостока и из Владивостока, осмотра и растаможки. Остаток переводится в юани по курсу ЦБ с наценкой — именно он уходит в фильтр цены che168. Сколько и на что уходит денег, видно на плашке под формой и на странице результатов.
4. Создаётся `SearchRequest` со снимком курса CNY/RUB и снимком расходов.
5. У che168 запрашиваются две сортировки:
   - `sort=2` — по возрастанию цены;
   - `sort=1` — по убыванию цены.
6. Из выдачи убираются дубли и предложения вне фильтров, берутся 3 + 3.
7. По каждому автомобилю загружается детальная карточка: все фото, пробег, двигатель, КПП, город, продавец, описание.
8. Цена в рублях считается по курсу на момент поиска: `CNY × rate × (1 + markup%)`.
9. Результаты сохраняются в БД, страница результатов доступна по короткому `PublicId` после входа.

Ограничение по умолчанию: до 4 страниц выдачи на каждую сортировку (настраивается в `appsettings.json` → `Search`).

## Расчёт стоимости

Бюджет клиента считается «под ключ»:

1. **Автомобиль** — цена площадки, пересчитанная по курсу ЦБ.
2. **Осмотр** — фиксированно 900 ¥.
3. **Доставка до Владивостока** — сумма в юанях, иенах или вонах по курсу ЦБ.
4. **Таможня** — коммерческий расчёт 2026 года:
   - пошлина по возрасту, объёму и типу двигателя;
   - акциз по мощности;
   - НДС 22% от стоимости, пошлины и акциза;
   - утилизационный сбор по объёму, мощности и возрасту;
   - сбор за таможенное оформление по стоимости.
5. **Брокер + лаборатория** — 140 000 ₽.
6. **Наша комиссия** — 150 000 ₽ для автомобилей до 3 млн ₽; свыше — по 10 000 ₽ за каждые начатые 100 000 ₽.
7. **Банковская комиссия** — 2,5% от суммы всех перечисленных расходов.
8. **Доставка до города клиента** — отдельная галочка и тариф из справочника «Доставка из Владивостока».

Для поиска по бюджету стоимость автомобиля подбирается обратным расчётом: система находит максимальную цену авто, при которой итог «под ключ» не превышает бюджет. Комиссия и банковский процент при этом тоже входят в бюджет.

Мощность двигателя che168 не передаёт. В поиске по бюджету она вводится вручную, а в карточке автомобиля подставляется из названия, если там указано «…马力», иначе её можно поправить вручную. Для электромобилей используется отдельная шкала утильсбора.

На публичной карточке клиент видит только итоговую стоимость под ключ, без внутренней расшифровки.

## Настройки

`appsettings.json`:

- `ConnectionStrings:DefaultConnection` — SQLite. Можно заменить на SQL Server/PostgreSQL, добавив соответствующий EF-провайдер.
- `Che168:*` — адреса API, версия клиента, таймаут, шаблон ссылки на оригинал.
- `Currency:*` — URL ЦБ РФ, fallback-курс, период обновления.
- `Search:*` — размер страницы, глубина выборки, конкурентность загрузки деталей.
- `Seed:*` — стартовый администратор и шаблон ссылки che168.

Часть настроек меняется в админке: **Курс валют**, **Источники**, **Пользователи**, **Тарифы** и **Карточки клиента**. Страница **Интеграция** показывает параметры che168 и ограничения источника только для чтения.

Клиентские тарифы и реквизиты публичной карточки:

- **Тарифы**: доставка до Владивостока, доставка из Владивостока в город клиента, осмотр автомобиля и растаможка. Тариф можно сделать тарифом по умолчанию и отключить без удаления.
- **Карточки клиента**: название на публичной странице, публичный адрес сайта для ссылок и контакты менеджера. В карточке фиксируются дата формирования и курс расчёта, поэтому изменение курса или тарифов позже не меняет уже отправленное предложение.

## База данных и доступы

- Сейчас используется SQLite (`Data/diavto.db`), доступ через **EF Core 10** и миграции.
- Для production рекомендуется **PostgreSQL 16/17** + Npgsql (альтернатива — SQL Server). Нужно заменить провайдер EF Core и строку подключения; схема уже provider-agnostic.
- Пользователи хранятся в ASP.NET Core Identity (таблицы `AspNetUsers`, `AspNetUserClaims` и т.д.).
- Доступ к разделам админки выдаётся по страницам: права хранятся как claims `admin_page` в БД. Роль `Admin` всегда видит все разделы. Изменения прав применяются после повторного входа пользователя.

## Второй источник

В БД создаётся запись `source-2` с названием «Второй сайт». Она отображается второй вкладкой и показывает заготовку, пока не подключён адаптер.

Чтобы подключить реальный сайт:

1. Реализуйте `IMarketplaceClient` в `Features/Marketplaces`.
2. Зарегистрируйте клиента в DI в `Program.cs` (как `Che168ApiClient`).
3. Заполните URL, шаблон ссылки и атрибуцию в **Админка → Источники**.
4. Включите источник и синхронизируйте каталог.

Вкладка появится на странице поиска автоматически по данным `SourceSites`.

## Ограничения и важные оговорки

- Интеграция с che168 использует **неофициальный мобильный API**. Он может измениться без предупреждения, ввести ограничения или потребовать авторизацию. Все запросы выполняются с задержками и лимитами, без обхода капчи и авторизации.
- Фотографии и данные принадлежат **che168.com / Autohome**. В интерфейсе указан источник и ссылка на оригинал. Перед публичным запуском:
  - согласуйте использование материалов и логотипа с правообладателем;
  - добавьте официальный логотип через `Источники → URL логотипа`;
  - проверьте условия использования сайта и требования к атрибуции;
  - не убирайте ссылку на оригинальное объявление.
- Рублёвая цена в карточке автомобиля — **ориентир** и не включает доставку, таможню, утилизационный сбор, сертификацию и услуги посредников. При поиске по рублёвому бюджету эти расходы вычитаются заранее и показываются отдельной плашкой — в подборку попадают автомобили в пределах остатка.
- Фильтра по мощности (лошадиным силам) нет: che168 не передаёт мощность ни в выдаче, ни в детальной карточке, а в нашей БД отдельного справочника характеристик нет. Для такого фильтра нужен сторонний каталог мощности по модели/году/мотору.
- SQLite подходит для MVP и небольшой нагрузки. Для production лучше PostgreSQL/SQL Server, кэш и отдельный сервис ingestion.
- Ссылки на карточки che168 могут открываться с мобильной версией сайта; шаблон меняется в админке.
- Внешние изображения отдаются CDN источника. Сервер выставляет `Referrer-Policy: no-referrer`, чтобы избежать блокировки хотлинка. Для повышенной надёжности можно добавить проксирование изображений.

## Production checklist

- [ ] Сменить пароль администратора, отключить/переопределить `Seed`.
- [ ] Включить HTTPS и HSTS (для публичного адреса с доменом).
- [ ] Заполнить тарифы доставки, осмотра и растаможки, проверить расчёт на тестовой карточке.
- [ ] Указать публичный адрес сайта в **Карточки клиента**.
- [ ] Перейти на PostgreSQL или SQL Server.
- [ ] Настроить резервное копирование БД.
- [ ] Добавить rate limiting для поисковых запросов.
- [ ] Вынести фоновые задачи в отдельный worker/queue.
- [ ] Добавить кэш каталога и курса.
- [ ] Проксировать/кешировать изображения, если CDN начнёт блокировать запросы.
- [ ] Согласовать использование данных и логотипа che168.
- [ ] Проверить, что публичная карточка не индексируется поисковиками (`noindex`).
- [ ] Мониторинг `/healthz` и ошибок источников.
