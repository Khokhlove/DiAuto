# Интеграция с che168.com

Реализация: `src/DiAvto.Web/Features/Marketplaces/Che168`.

Используется мобильный JSON API che168 (Autohome). Это не официальный публичный API с документацией, поэтому поведение может измениться. Все запросы подписываются тем же способом, что и в мобильном web-клиенте площадки.

## Хосты

| Назначение | Хост |
|---|---|
| Каталог и поиск | `https://api2scsou.che168.com` |
| Детальная карточка | `https://apiuscdt.che168.com` |
| Публичная карточка | `https://m.che168.com/cardetail/index?infoid={infoid}` |

Хосты и шаблон ссылки вынесены в `appsettings.json` → `Che168`.

## Подпись

Каждый GET-запрос содержит:

- `_appid=2sc.m`;
- `v=11.41.5`;
- `_subappid=2sc.pc`;
- `_sign=<md5>`.

Порядок вычисления в `Che168RequestSigner`:

1. В параметры добавляются обязательные поля.
2. Ключи сортируются по алфавиту.
3. Конкатенируются пары `key + value` (без `=`).
4. Строка оборачивается секретом: `secret + payload + secret`.
5. Считается MD5, hex в нижнем регистре.
6. В URL значения кодируются через `Uri.EscapeDataString`, `_sign` добавляется последним.

Секрет и ключ восстанавливаются в коде из зашифрованного материала. Не публикуйте их и не используйте интеграцию способом, нарушающим правила площадки.

## Endpoint'ы

### Бренды

`GET /api/v2/getbrands`

Структура ответа:

- `result.hotbrand[]` — популярные бренды;
- `result.brands[]` — группы `{ letter, brand[] }`;
- у бренда: `bid`, `name`, `py`, `icon`.

Бренды кешируются в таблице `Brands`.

### Модели бренда

`GET /api/v2/getseriesbybrandid?brandid={bid}`

Ответ: `result.list[]` — группы `{ name, item[] }`, у модели `sid`, `sname`, `py`, `icon`, `pricerange`.

Модели кешируются в `CarSeries` и подгружаются при первом выборе бренда.

### Поиск

`GET /api/v11/search`

Параметры, которые использует проект:

| Параметр | Значение |
|---|---|
| `cityid` | `110100` по умолчанию. В мобильной выдаче фильтр по городу фактически игнорируется, поэтому в публичной форме город не используется. |
| `brandid` | ID бренда |
| `seriesid` | ID модели (опционально) |
| `pageindex` | с 1 |
| `pagesize` | 1..20 |
| `ssnew` | `1` |
| `sort` | `0` — релевантность, `1` — сначала дорогие, `2` — сначала дешёвые |
| `price` | диапазон в 万 юаней, например `10-20` |
| `mileage` | диапазон в 万 км, например `0-5` |
| `agerange` | возраст в годах, например `1-3` |
| `displacement` | объём двигателя в литрах, например `1.5-2.0` |
| `gearbox` | `1` — механика, `2` — автомат |
| `fueltype` | `1` — бензин, `2` — дизель, `3` — гибрид, `5` — PHEV, `6` — EREV, `7` — электро |
| `powertrain` | `1` — передний привод, `2` — задний, `3` — полный |
| `classid` | класс автомобиля: `3` — компактный, `4` — средний, `17/18/19/20` — SUV и т.д. |
| `structure` | тип кузова: `2` — седан, `1` — хэтчбек, `3` — лифтбек, `4` — универсал и т.д. |
| `environmental` | экокласс: `6` — Китай-6, `5` — Китай-5, `106` — Евро-6 и т.д. |
| `setcount` | количество мест: `2`, `4`, `5`, `6`, `7`, `99` (7+) |

Мощность двигателя в выдаче и карточке che168 не передаётся, поэтому фильтр по мощности недоступен без отдельного справочника характеристик.

Ответ: `result.carlist[]`, `totalcount`, `pagecount`, `pageindex`, `filters`, `otherlist`.

Ключевые поля машины:

- `infoid` — ID объявления;
- `carname` — название;
- `price` — цена в 万 CNY;
- `mileage` — пробег в 万 км;
- `firstregyear` — год;
- `cname` — город;
- `imageurl`, `photocount`;
- `dealerid`, `dealerlevel`;
- `displacement`, `environmental`, `isnewenergy`.

`otherlist` содержит рекламные и рекомендательные блоки, проект их игнорирует.

### Детальная карточка

`GET /apic/v2/car/getcarinfo?infoid={infoid}&deviceid={deviceid}`

Ключевые поля:

- `price`, `guidanceprice` — в 万 CNY;
- `mileage` — в 万 км;
- `firstregyear`, `firstregdate`, `firstregstr`;
- `piclist[]` — массив URL фотографий;
- `brandname`, `seriesname`, `carname`;
- `displacement`, `gearbox`, `fuelname`, `environmental`, `colorname`, `levelname`;
- `transfercount`, `cname`, `dealerid`, `remark`, `publicdate`.

`piclist` может быть короче `photocount`; проект сохраняет фактически полученные фотографии и показывает их количество.

## Особенности данных

- Цены и пробег приходят в «万» (10 000). В БД проект хранит уже полные CNY и километры.
- Названия и часть полей на китайском; русские названия брендов задаются словарём `BrandLocalization` и при необходимости расширяются.
- Модель (`seriesid`) в выдаче может отсутствовать в локальном кеше, если её ещё не синхронизировали. `CatalogService.GetSeriesAsync` подгружает модели при первом обращении.
- Выдача может содержать рекламные позиции и дубли; проект фильтрует нулевые цены и дубликаты по `infoid`.
- Для поиска крайних цен используются сортировки `sort=2` и `sort=1`, а не полная загрузка всех страниц.

## Ошибки и устойчивость

- HTTP-клиент повторяет запрос до 3 раз при сетевых ошибках, 429 и 5xx.
- Таймаут по умолчанию — 35 секунд.
- Если детальная карточка не загрузилась, карточка всё равно сохраняется по данным выдачи.
- Ошибка поиска фиксируется в `SearchRequests.Status = Failed` с текстом ошибки; админ видит её в истории.

## Правовая оговорка

Перед публичным запуском необходимо:

- согласовать использование данных, фотографий и логотипа с правообладателем;
- сохранить видимую атрибуцию и ссылку на оригинальное объявление;
- соблюдать условия использования che168.com и применимое законодательство;
- не обходить технические ограничения, капчу и авторизацию.
